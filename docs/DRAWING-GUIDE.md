# 画图操作手册

从零到一份能跑通寻路的数据。全程用编辑器（`npm run editor`），不用手写 GeoJSON。

---

## 0. 一分钟总览

```
① 平面图放进 plans/     →  ② npm run editor 打开编辑器
③ K 两点定比例          →  ④ M 量另一条距离核对（关键！）
⑤ W 画走廊/大厅         →  ⑥ F 画面状设施（门自动生成）
⑦ P 放点状设施          →  ⑧ O 画障碍物（柱子/柜台）
⑨ C 连扶梯/电梯/安检    →  ⑩ 保存 → 校验，清掉所有 ERROR → ⑪ 勾 verified
```

顺序不能乱：每一步都依赖上一步的产物。

| 步骤 | 为什么必须在这个位置 |
|---|---|
| 先校准 | 比例不对，后面画的每一个坐标都是错的，且**返回去改要重画** |
| 先画可通行面 | 设施的门、障碍物、连接件的端点都要吸附到它上面 |
| 点状设施在面状之后 | 点状设施要判断「是不是落在某家店里面」（重复录入） |
| 连接件最后 | 端点要落在可通行面里，面还没画就没法放 |

---

## 1. 准备平面图

把图片丢进 `projects/bdia-nav/plans/`：

```
plans/
  4f.png      出发层（值机/安检）
  3f.png      候机层
  2f.png      到达层
  ...
```

建议文件名带楼层号，编辑器的下拉框按文件名排序，找得快。

**要求**：
- **一张图只放一层**。多层拼一张图上没法校准（各层比例可能不同）
- **必须是真正的正射平面图，不能是效果图/轴测图/照片**。透视变形会让任何线性校准都失效
- 长边 2000~4000 px 合适

> PDF 先转 PNG（300 dpi 左右）。

## 2. 启动

**Windows：双击 `启动编辑器.cmd`。** 或者在命令行里：

```bash
cd projects/bdia-nav
npm run editor
```

浏览器自动打开 `http://127.0.0.1:5173/editor/`。左侧「楼层」列出 `manifest.levels` 里的所有楼层，灰点的是还没画的。

### ⚠️ 不要双击 `editor/index.html`

用 `file://` 打开**一定是空白页**，原因有两个：

1. 浏览器会以 **CORS** 为由拒绝加载 ES 模块（`file://` 的 origin 是 `null`）
2. 没有服务可问，`fetch('/api/data')` 读不到 `data/source/`，也存不回去

页面现在会显示这段说明而不是空白，但正确做法还是从服务走 —— **编辑器需要服务来读写 `data/source/` 和调用校验器，这是设计如此。**

### 服务窗口别关

那个命令行窗口就是服务本体。**关掉它 = 编辑器断线**（界面还在，但保存和校验会失败，刷新就变成「连不上编辑器服务」）。

端口被占用的话换一个：

```bash
node tools/editor-server.mjs --port 5174
```

### 起不来怎么办

页面会直接告诉你原因，不会给你一片空白：

| 现象 | 原因 |
|---|---|
| 「不能直接用 file:// 打开」 | 你双击了 HTML。双击 `启动编辑器.cmd` |
| 「加载 app.js 失败」 | 服务没在跑，或者地址/端口不对 |
| 「编辑器没能启动」 | 服务在跑但初始化失败。按 F12 看控制台；跑 `npm run validate` 查数据，跑 `npm run editor:boot` 查界面 |

## 3. 校准 —— 全流程最关键的一步

**做错了，后面全白干。** 按 `K` 进入「两点定比例」。

### 怎么选这两个点

在平面图上找两点，你**确切知道真实距离**。优先选：

1. **柱网间距** —— 最可靠，机场柱距通常 9m / 12m / 18m，且图上标注清楚
2. **建筑总宽/总长** —— 航站楼核心区跨度这类公开数据
3. **已知设施尺寸** —— 比如跑道的宽度等级、登机桥的间距

**两点要尽量远**（至少占图宽的 1/3）。点得越近，像素量测的相对误差被放大得越厉害。

### 操作

1. 按 `K`
2. 在图上点第一个点
3. 点第二个点
4. 弹窗里填：
   - **真实距离**（米）
   - **方位角**：这两点在真实世界里是朝哪个方向？
     - 不确定 → 选「不校正旋转」
     - 竖着的柱网 → 选「正北」
     - 横着的柱网 → 选「正东」
5. 点「应用」

侧栏会显示 `1px = 0.xxxx m`。

### ★ 核对（别跳过这步）

按 `M` 进入「量距核对」，**再量一条你已知的、和刚才方向不同的距离**（比如刚才量的是东西向柱距，这次量南北向的）。

对比编辑器显示的距离和真实值：

| 误差 | 结论 |
|---|---|
| < 1% | ✅ 图是正射的，比例可信 |
| 1% ~ 3% | ⚠️ 可以接受，但要注意 |
| > 3% | ❌ **图有透视变形，或者你把图缩放拉伸过**。换一张图，或者分区段分别校准 |

这一步是唯一能发现「这张图根本不能用来量距离」的手段。如果你用的是从网上找的效果图截图，这里一定会爆。

### 旋转没对齐会怎样

如果平面图没和正北对齐而你选了「不校正旋转」：**所有距离是对的，但方向全错**。导航里「向北走 30m」会变成「向东北走 30m」。

判断方法：看画布上的坐标轴（青色横线是 x=0 正东轴，金色竖线是 y=0 正北轴）。如果你知道图里某个方向是正北，它应该和金色轴线平行。

### 各层共用一套校准？

**默认不要共用。** 每层图是独立文件，像素尺度通常不同。

但如果你是从同一个 PDF 分层导出的、且导出时缩放一致，可以用面板底部的「复制到其他层…」把比例和旋转复制过去。**原点仍然各层独立**（每层图的原点像素位置不同）。

### 一层放多张底图

一层可以放任意多张底图 —— 比如把「平面图」和「消防疏散图」叠在一起对照，或者一张总图配几张局部放大图。

在面板顶部 **「＋ 添加底图…」** 里选图片即可。同一张图可以加多次（放在不同位置）。

每张底图**独立**控制：

| 控件 | 说明 |
|---|---|
| **比例 m/px** | 缩放。用「两点定比例」自动算，或手填 |
| **旋转 °** | 相对正北的旋转角 |
| **原点 px** | 这张图的哪个像素对应本地坐标 (0,0) |
| **微调 m** | 在本地坐标系里平移多少米（不动原点，用来对齐） |
| **不透明度** | 0~1，叠图时把下面的调淡 |
| **↑ ↓** | 叠放顺序（列表靠后的盖在前面上） |
| **◉ / ◌** | 显示 / 隐藏 |
| **×** | 移除这张（不影响别的） |
| 标题输入框 | 给这张起个名字，多张时好区分 |

**当前底图**：点卡片空白处切换。画布上会用**青色虚线框**标出当前底图的范围。按 `K`（两点定比例）和 `M`（量距核对）作用的都是当前底图。

> 多张图的典型用法是**对照**：叠起来后各自调「微调 m」让它们对齐，然后把参考那张调淡。
> ⚠️ **每张图都要单独校准** —— 新加进来时是默认的 `0.5 m/px`，不校准直接用会让这张图上的距离全错。

## 4. 画可通行面（`W`）

**这是寻路的地基。** 可通行面 = 真正能走的地面。

先画什么：
1. **主走廊 / 中央大厅** —— 最大的一块
2. **各指廊** —— 一条条画，让它们的端部和走廊**共边**（共享一段边界）
3. **排队区、连接厅** —— 小区域

选中「种类」（`hall` / `corridor` / `pier` / `queue` / `lobby` / `bridge` / `platform`），然后依次点击顶点，`Enter` 闭合。

### 三个要点

**① 相邻面要共边，不能留缝**
两个面共享一段边界 = 连通。留了缝（哪怕 10cm）就会被当成两座孤岛，路径过不去。
编辑器的吸附会自动帮你贴上去（靠近已有边时会显示青色吸附圈）。

**② 不同隔离区的面不能贴在一起**
安检前的走廊和安检后的候机区如果共边了，校验器会报 `E_ZONE_ADJACENT_NO_GATE` —— 因为那意味着旅客可以不经过安检直接走到登机口。
正确做法：**拉开一段距离**（安检通道本身的长度，15~25m），中间用 `security` 连接件跨过去。

**③ 别把店铺画进可通行面**
店铺是「挖掉」的区域，是**面状设施**（下一步 `F`）。可通行面画大了会把店铺吞掉，路径就会穿店而过。

> ⚠️ **可通行面不是寻路图。** 它只负责三件事：① 承载隔离区语义 ② 提供宽度/几何校验的依据 ③ 判断「这个 POI 在不在可走区域里」。
> **真正决定路径怎么走的是通行线（`L`）**，见下一节。

---

## 4.5 画通行线（`L`）—— 寻路图本身

**这是整个项目最重要的一层。** 旅客看到的每一步指令，都是从你画的这些线生成的。

### 为什么不是用可通行面算路？

用面算路（navmesh）几何上更优，但有两个致命问题：

| | 用面（navmesh） | 用线（通行线） |
|---|---|---|
| 转弯点 | 漏斗算法算出的**障碍角点** | **你放节点的位置** |
| 指令 | 「向东南方走 87 米」—— 在大厅里没法执行 | 「沿中央通道向前 60 米，经过问询台后右手边是星巴克」 |
| 一层要画 | 完整轮廓 + 每个店铺挖洞 + 每根柱子，**几百个顶点** | 主干 + 支线，**几十个顶点** |
| 编译 | Recast 体素化 → 区域 → 网格，几百 KB | **无**，图就是数据 |

对导览 App 来说，**「可执行」压倒「最短」**；对一个人画完整个航站楼来说，**绘制成本决定项目能否完成**。

### 画法

按 `L`，点着加顶点，`Enter` 结束（或者**再点一次最后一个顶点**，双击也走这条路）。

**★ 两条线交叉即连通，不用手工打断。**

```
     │                    │
─────┼─────    ← 画一条横线穿过去，交叉处自动生成四岔路口
     │
```

这是平面上的物理事实 —— 在同一个可通行区域里，交叉点你确实走得过去。所以画长线穿过去就行，**不要**在路口把线切断成好几段。

例外：视觉上交叉但实际不连通（跨层天桥、玻璃隔断），加 `bridge: true`。

### 三条硬规则

| 规则 | 为什么 |
|---|---|
| **线必须落在同层同 zone 的可通行面内** | 否则路径穿墙。画完会立刻提示哪几个顶点越界 |
| **一条线不能跨隔离区** | 跨 zone 只能经连接件（安检/边检/海关/中转柜台）。这是「隔离区泄漏」的线版本，比面版本更直接 |
| **连接件的 from/to 必须落在某条通行线上** | 否则图会在这里断开，路径走不过去 |

好消息：编辑器里画完一条线会**立刻做这三项体检**并弹提示；正式的 9 条规则由 `npm run validate` 兜底。

### 端点要「有东西接住」

一条通行线的端点如果没有接住任何东西，就是**悬空端点**（`W_PATH_DANGLING`）。旅客永远走不到那里，也不会被指引到那里。

端点应该落在：**路口 / 某个店铺的门 / 某个登机口旁边 / 某个扶梯口**。

> 判定半径是 15m（`thresholds.pathDanglingAnchorDistance`）。这个数**必须 ≥ 指廊半宽** —— 指廊通常 28m 宽，中线到两侧登机口约 12~14m，阈值太小会把所有正常的指廊末端都报成悬空。

### 线的属性

| 属性 | 说明 |
|---|---|
| `kind` | `spine` 主通道 / `corridor` 走廊 / `pier` 指廊 / `branch` 支线 / `queue` 排队折线 / `walkway` 自动步道 / `staff` 员工通道 |
| `name` | **会出现在转向指令里**（「沿中央通道向前 60 米」），所以起得像人话 |
| `minWidth` | 这条通道的最小宽度，用于无障碍路线筛选 |
| `accessible` | 轮椅/婴儿车/大件行李能否走 |
| `speedFactor` | 速度系数：自动步道 1.6、楼梯 0.6、坡道 0.8。算耗时用 |

### 「路网节点」图层

图层面板里打开 **路网节点**，画布上会叠加出**编译后的图**：

- **小白点** = 度数 2 的普通节点（弯折处）
- **大黄点 + 数字** = **路口**（度数 ≥ 3），数字是连接条数

这是验证「交叉即连通」最直观的方式：**你画两条线穿过去，交叉点上会立刻冒出一个黄点。**

## 5. 画面状设施（`F`）

面状设施画在走廊**外侧**，一条边和走廊重合：

```
            ┌─────────┐
            │  店铺   │  ← 面状设施（不可走）
            └────┬────┘
                 │ ← 门自动放在这条公共边上
   ┌─────────────┴──────────────┐
   │      走廊 / 大厅            │  ← 可通行面
   └────────────────────────────┘
```

选好「类别」（`dining` / `retail` / `duty_free` / `restroom` / `airline_lounge` …），画完 `Enter` 闭合。

> **它和点状设施是同一个图层、同一张类别表。** 选哪个只取决于「它是不是一块地」——
> 星巴克是一家店（面），饮水机是一个点。改主意了就把几何换掉，属性一个不用动。

### ★ 门是自动生成的

闭合的瞬间，编辑器会：
1. 找这个面和同层所有可通行面的**共享边**
2. 取**最长的那条**（如果它贴了两条走廊）
3. 把**重叠段的中点**设为门

所以「门必须在走廊边界上」这条规则**自动成立**，不用记。

如果提示「找不到与可通行面的共享边」，说明没贴到走廊上 —— 挪过去，或在属性面板点「自动重算门」。

### 能穿行吗

默认**不能**（`through: false`）。店铺不能当通道，否则路径会穿店而过。只有真正贯通的通道（比如中央的连廊商铺）才勾选「可穿行」。

## 6. 放点状设施（`P`）

先在提示条里选「类别」（60+ 种已预置，和面状设施共用一张表），然后逐个点击放置。

放完之后，在右侧属性面板里补：
- **中文名 / 英文名** —— 双语站点必须都有，缺了英文名校验器会警告
- **别名** —— 用逗号分隔。「星巴克」要能被「Starbucks」「咖啡」搜到，这是搜索体验的关键
- **位置描述** —— 如「3F 北指廊西侧」，搜索结果副标题用
- **营业时间**

**点状设施会自动继承它所在可通行面的隔离区**，不用手填 zone（填错是常见错误，校验器会抓）。

> ⚠️ **别为一家店再放一个点。** 如果你已经画了「星巴克」这个面状设施，就不要再在同位置放一个点状设施 ——
> 那会在搜索里出现两个「星巴克」。校验器会报 `W_POINT_INSIDE_AREA_FACILITY`。
> 一个设施 = 一条记录。

## 7. 画障碍物（`O`）

柱子、柜台、设备、绿植、不可通行的员工区。

**障碍物不是设施** —— 没有名字、没有类别，不会被搜到，也不会成为导航目的地。它只是一个要从可通行面里**扣掉**的形状。

### ★ 和面状设施的定位规则正好相反

```
   面状设施                          障碍物
   ┌─────────┐                              ┌───┐
   │  店铺   │  ← 画在走廊「外侧」           │ ▨ │  ← 画在走廊「内部」
   └────┬────┘     只与走廊共边              └───┘     被扣除
        │ door
   ┌────┴────────────────┐              ┌───────────┴────────┐
   │   走廊 / 大厅        │              │   走廊 / 大厅       │
   └─────────────────────┘              └────────────────────┘
   靠门连接，是「目的地」                 是「障碍」，路径要绕开
```

画在走廊外面的障碍物**什么也挡不住**（报 `E_OBSTACLE_OUTSIDE_WALKABLE`）。画完编辑器会立刻提示。

### 为什么不把柱子塞进可通行面的洞里

技术上可行（Polygon 支持洞），但画起来极其痛苦：大厅里几十根柱子，每加一根都要回头改大厅的环。

分成独立的扣除层之后：**大厅画一次，柱子一个个盖上去**。改柱子不动大厅。

> 两种做法都行，**别重复**：如果走廊本来就画得绕开了柱子，就不用再画障碍物了。

## 8. 连连接件（`C`）

这是「哪个扶梯连着另一层的哪个扶梯」的落点。

**操作**：按 `C` → 点**起点** → 点**终点**。

编辑器会自动：
- 判断起点/终点各自落在哪个可通行面里，取出对应的隔离区
- **如果两端隔离区不同，自动从 `zoneRules` 里挑一个合法的连接件类型**（比如从 landside 到 airside_domestic 会自动选 `security`）
- 按类型自动填 `travel_time` / `wait_time` / `accessible` / `bidirectional`

**跨层怎么办**：先把两层都画好，然后在下面那层的扶梯口点起点、切到上面那层的对应位置点终点。
> 用左侧「幽灵层」把下一层以低透明度叠上来，就能看清上一层的扶梯口该画在哪。

### 画完立刻看提示

| 提示 | 含义 |
|---|---|
| ✓ 落在可通行面 xxx 内 | 正常 |
| **✗ 不在任何可通行面内** | **路径会断在这里**，把端点挪进走廊 |
| 跨越 landside → airside_domestic，已自动选 security | 正常，隔离区跨越 |

属性面板里也会对起点/终点分别显示这个判定，红色就是错的。

### 扶梯默认是单向的

新增的扶梯 `bidirectional: false`。这是故意的 —— 大兴大量扶梯是单向的，写成双向会规划出物理上过不去的路线。

确实是双向的，在属性面板里勾上「双向」。

分时反向的（白天上行、夜间下行），在 `connectors.geojson` 里手写 `schedule` 数组。

### 电梯要成对配置

同一部电梯在每层都有一个站点，**每层站点之间都要连一条边**。不要只连相邻两层。

（编译期会把它们合并成一个「井节点」，避免等待时间被重复计算 N 次。）

---

## 9. 保存与校验

- `Ctrl+S` **保存** → 直接写进 `data/source/`，不经过下载再搬文件
- 点 **校验** → 在浏览器里跑完整的校验器，结果显示在右下角

**校验结果怎么处理**：

| 严重度 | 处理 |
|---|---|
| **ERROR** | **必须清掉**。点问题条目会跳到出问题的要素并选中它 |
| WARN | 多数是「其他楼层还没画」的预期提示。逐条看，真问题就修 |
| INFO | 提示性质，比如「这个连接件是单向的」 |

常见的 ERROR 和修法见 `docs/DATA-SCHEMA.md` §10 的速查表。

### 最后一步：勾 `verified`

对照官方平面图核实过的要素，在属性面板勾上「已核实」。校验器会统计这个比例 —— 是你知道「哪些数据可信」的唯一凭据。

## 11. 跨层对齐

这是最容易出问题、也最需要工具支持的地方。

**症状**：路径算出来了，但扶梯上下端差了 5 米 —— 旅客被引导到一个不存在的位置。

**原因**：各层平面图的原点/比例/旋转不一致。各层是独立文件，像素尺度天然不同。

**编辑器的做法**：每层一份独立校准，但**映射到同一个本地米坐标系**。只要每层都按 §3 正确校准，跨层就自动对齐。

**核对方法**：
1. 在 3F 画好扶梯口
2. 左侧「幽灵层」选 4F，把它叠上来
3. 在 4F 画扶梯的另一端，对准幽灵层上的位置
4. 用侧栏「微调 m」微调 4F 底图的位置，让扶梯井视觉上重合

**校验器会兜底**：每个跨层连接件都会检查两端水平偏差是否超过该类型的容差（电梯 1.5m / 楼梯 2m / 扶梯 3m），超了报 `E_CONN_MISALIGNED`。

## 12. 常见问题

**画布一片空白**
- 没选平面图：左侧「平面图与校准」的下拉框选一张
- 矢量在视野外：按 `F` 适应视图
- 平面图不透明度是 0：调滑块

**图在画布上位置不对 / 尺寸不对**
- 重新按 `K` 校准
- 检查「原点 px」和「旋转 °」是不是被手动改过

**量出来的距离总是差 30%**
- 你可能在用经纬度思考。本项目的坐标单位是**米**，不是度。见 `docs/DATA-SCHEMA.md` §0

**画好的面点不中**
- 图层被隐藏了（左侧「图层」里的勾）
- 面在别的楼层（左侧「楼层」切过去）

**面状设施的门位置不对**
- 在属性面板点「自动重算门」
- 还是不对 → 设施没和走廊共边。检查两者是否真的贴在一起（放大看有没有缝）

**校验器报 `E_DISCONNECTED`**
- 有走不到的孤岛。点这条问题会跳到出问题的面
- 常见原因：两个走廊之间留了缝没贴紧，或者漏了一条跨区的安检连接件

**路径撞上柱子**
- 用 `O` 在走廊**内部**盖上障碍物。画在外面报 `E_OBSTACLE_OUTSIDE_WALKABLE`（什么也挡不住）
- 注意方向和面状设施相反：设施画外侧，障碍物画内侧

**搜到两个「星巴克」**
- 同一家店录了一条面状设施 + 一条点状设施。合并成一条
- 校验器会报 `W_POINT_INSIDE_AREA_FACILITY`

## 13. 建议的推进节奏

**第一轮不要铺全楼层。** 先做窄而深的一小块：

1. 画 3F 的**中央大厅**一块（`W`）
2. 画**一家店铺**（`F`，验证自动门）
3. 放**两个登机口**（`P`）
4. 画**一根柱子**（`O`，验证障碍物扣除）
5. 放**一个安检点**（`C`，跨 landside → airside）
6. 保存 → 校验 → 清 ERROR

做完这六个，整条工具链就验证完了。之后铺数据就是重复劳动，不会再遇到结构性问题。

全楼层铺开后，最容易返工的是：
- **隔离区划分**（安检前/后边界画错，后期要重新切分面）
- **跨层对齐**（各层校准不一致，后期要重新校准并整体位移）

这两个建议在铺量之前先想清楚。
